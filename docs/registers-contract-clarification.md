## Answers to the seven review questions

1. **Affine convention:** confirmed row-major `[a,b,c,d,e,f]`, `x'=a*x+b*y+c`, `y'=d*x+e*y+f`. Identity `[1,0,0,0,1,0]`. The original [API behavior document](api/README.md) already specifies this; it was missing from the two downloaded artifacts. All eight EXIF mappings have actual decoded-pixel tests. Result geometry is already original encoded crop geometry, so do not apply internal transforms again. Cross-app nonidentity acceptance remains to be exercised.

2. **Executable semantics:** [semantic rules](api/semantic-validation.md), `scriptalocal/contracts.py` and `scripts/validate_contract.py` provide the exact current model checks. The downloadable offline bundle includes these files, dependency pins and both canonical documentation and examples. Blank line/cell, null aggregates, failed-with-no-lines and warning scopes are specified there. Raw fields remain line-level; do not add cell raw-state wire fields. JSON Schema alone is insufficient. Both service and app must retain review requirements beyond model validity.

3. **Revision race/identity:** current design is latest-revision GET/status, with no old-revision query route. Bind to accepted job/revision, validate returned job/revision before import, and retain fetched raw bytes/digest. GET calls are not one cross-request snapshot. If the revision changes, enter explicit reconciliation, not automatic mapping/publication. Prior stored raw history must remain immutable. Text-only revisions are intended to retain unchanged cell/line IDs; geometry revisions may replace IDs and invalidate mappings. Actual revision execution/history retrieval remains HTR-018, so these are required design semantics, not deployed guarantees. Initial adapter correction calls remain out of scope.

4. **Defaults on the wire:** for future server responses, use full model serialization, including version/default/null fields; do not use exclude_unset, exclude_defaults or exclude_none. The incoming v1 schema/model still permits omission of fields with explicit defaults and rejects incompatible explicit versions. Offline validation applies those documented defaults, but the caller must retain the original raw bytes so absence is not mistaken for an observed fact. No server serializer exists yet; verifying complete responses remains HTR-017 acceptance. `warnings:[]`, `cancel_requested:false`, `error_code:null`, default api_version/coordinate_space/transforms have their model-defined meanings, not evidence of an inference action.

5. **Idempotency/retention:** implemented queue normalization uses complete `JobOptions.model_dump(mode='json')`; omitted/default/null optional values normalize identically where allowed. Missing/null corrected_dividers are the same detection request; [] is distinct and means one cell. Missing keep_reference equals false; null is invalid. Omitted/null model_id is the server default request; an explicitly named model is a distinct option even if it currently matches that default. client_reference participates in identity. Source metadata/content hash and pinned configuration SHA also participate. A configuration change can therefore conflict at the queue boundary: the future HTTP replay handler must resolve the existing operation's pinned configuration before claiming unchanged replay across deployments. Same-configuration lost-response/restart identity is proven by real PostgreSQL recovery tests; cross-configuration HTTP replay remains unverified. Keys persist with the job today; no timed key expiry/deletion is implemented. keep_reference is intended to protect reference jobs from automatic retention, never grant training consent. Retention windows, active deletion and reference protection still require HTR-024/029 implementation/verification; 30 days remains a proposal, not an active policy. No 410 or automatic re-enqueue should be inferred.

6. **Provenance/timing/resources:** pipeline_version/configuration_sha256 must identify exact detector/segmentation/recognition source and configuration, including package/model hashes and affine convention. The implementation needs a persisted manifest binding those identifiers; version strings alone do not establish this. Prototype reports include source hashes, but a full service pipeline manifest remains to be implemented. stage_seconds uses seconds, scoped to named stages; clients preserve unknown keys and must not infer wall-clock total from the sum. Queue/wall-clock timings require explicitly documented keys before use. Decoder limits are configurable and larger than the app's unchanged 4 MiB/16M pixels. Existing layout limits (256 manual dividers), per-cell segmentation limits (256 lines, 4M pixels per line), queue/artifact caps and the CLI's 2 MiB input cap are component limits, not an agreed public maximum result. Global cells/lines/text/result-byte caps and the app's 50-entry/2,000-part/200,000-character limits must be enforced explicitly before publication under HTR-017/021/024. Do not silently truncate a result to fit.

7. **Release prerequisites:** agreed: separate OCR HTTPS origin and scoped credential, trust/readiness/models, dedicated worker identity/connectivity, real cancellation/restart/publication tests and representative row quality remain release gates.
